# ข้อจำกัดของระบบและแผนการพัฒนาในอนาคต (Limitations & Future Milestones)
## HosPrime - Health Organization Operating System

เอกสารนี้ระบุข้อจำกัดในปัจจุบันของ **Knowledge Oracle MVP (Milestone 1)** และทิศทางในการพัฒนาในอนาคตตามทิศทางการสร้าง **Human-Centric Organizational Digital Twin (HODT)** และคลังข้อมูลอัจฉริยะของจังหวัด

---

## ⚠️ ข้อจำกัดในเวอร์ชันปัจจุบัน (Milestone 1 Limitations)

1. **การค้นหาเวกเตอร์ (Vector Search Scale)**:
   - เวอร์ชันปัจจุบันประมวลผลการคำนวณ Cosine Similarity ด้วย Python & NumPy บนหน่วยความจำ (In-memory) จากข้อมูลใน SQLite ซึ่งเหมาะสมและเร็วมากสำหรับคลังความรู้ระดับ MVP (~100-500 เอกสาร) แต่จะมีความหน่วงเพิ่มขึ้นเมื่อฐานข้อมูลเพิ่มขนาดเป็นหมื่นชิ้นข้อมูล
2. **ระบบการดึงข้อความ (Text Parsing)**:
   - รองรับไฟล์ PDF, DOCX, TXT และ MD ในแบบตัวอักษรดิบ ยังไม่รองรับการถอดรหัสรูปภาพ/ตาราง (OCR) หรือสแกนลายเซ็นบนหนังสือสั่งการที่เป็นไฟล์ภาพสแกน
3. **การเข้าถึงของปัญญาประดิษฐ์ (Sovereign Context)**:
   - อาศัยการเชื่อมต่อกับอินเทอร์เน็ตเพื่อเรียกใช้งาน Google Gemini API เป็นหลัก (แม้ว่าระบบจะเตรียมระบบสาธิตออฟไลน์แบบ Mock Fallback ไว้รองรับเมื่อเครือข่ายขัดข้อง) แต่สำหรับการใช้งานจริงในโรงพยาบาลหรือ สสจ. ที่ต้องการความปลอดภัยสูงสุด ระบบจะต้องเปลี่ยนผ่านไปใช้งาน Local LLM ในเครือข่ายภายในโรงพยาบาล
4. **ความสัมพันธ์ระดับความรู้**:
   - ปัจจุบันระบุความสัมพันธ์เบื้องต้นผ่านตาราง `EntityRelation` ของ SQLite และยังไม่ได้เชื่อมต่อระบบเข้ากับ Graph Database เช่น Neo4j จริงๆ

## 🚀 แผนพัฒนาในระยะถัดไป (Milestones 2 - 5 Roadmap)

ตามแผนแม่บทการพัฒนาองค์กรอัจฉริยะ (OITP/HODT):

### Milestone 2: Meeting Memory & Executive Dashboard
- **เป้าหมาย**: บันทึก จัดเก็บ และวิเคราะห์ความจำจากการประชุมราชการ สกัด Action Items และมอบหมายงานโดยอัตโนมัติ
- **สิ่งที่ต้องทำ**: เชื่อมโยงระบบแปลงเสียงเป็นข้อความ (Speech-to-Text) และระบบสกัดมติที่ประชุม

### Milestone 3: Executive Twin & Strategic Simulation
- **เป้าหมาย**: พัฒนา **Executive Digital Twin** (แบบจำลองผู้บริหารดิจิทัล) เพื่อประเมินสไตล์การร่างหนังสือและช่วยคัดกรองงาน
- **สิ่งที่ต้องทำ**: พัฒนา Role Twin และ Person Twin ตามรายละเอียดใน `IDEA_PLAN.md` เพื่อประเมินทัศนะและแนวทางการตัดสินใจย้อนหลัง

### Milestone 4: Provincial Health Brain (Knowledge Graph Integration)
- **เป้าหมาย**: พัฒนา **Oracle Knowledge Graph** โดยโยกย้ายความสัมพันธ์จาก `EntityRelation` บน SQLite เข้าสู่ **Neo4j** หรือ **Apache AGE**
- **สิ่งที่ต้องทำ**: พัฒนา Graph RAG (Graph-based Retrieval-Augmented Generation) ซึ่งจะทำให้ AI สามารถหาคำตอบที่มีความซับซ้อนระดับข้ามฝ่ายงานได้ดีขึ้น เช่น `"โครงการฝุ่น PM2.5 เชื่อมโยงกับรอง นพ.สสจ. ท่านใด และมีผลต่อดัชนีชี้วัดโรคปอดอุดกั้นเรื้อรัง (COPD) อย่างไร"`

### Milestone 5: Backoffice AI Workforce (Workflow Automation)
- **เป้าหมาย**: เปลี่ยน AI จากการตอบคำถาม (Oracle) มาเป็นหน่วยงานสนับสนุนที่ช่วยสั่งการและปฏิบัติตาม workflow โดยอัตโนมัติ เช่น การเตือนภัยโรคระบาดล่วงหน้าและการประสานงบภัยพิบัติ
- **สิ่งที่ต้องทำ**: เชื่อมต่อระบบ AI Runtime เข้ากับ Workflow engine เช่น **Temporal** หรือ **Camunda**
