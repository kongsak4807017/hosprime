### Source 1 — Obsidian Help: Internal links

Provenance:

```text
SOURCE_TITLE = Internal links - Obsidian Help
SOURCE_URL = https://obsidian.md/help/links
SOURCE_TYPE = official vendor help page
RETRIEVED_DATE = 2026-07-09
REVIEW_STATE = staged_only
```

Relevant finding:

- Obsidian supports internal links between notes using either Wikilink format, e.g. `[[Three laws of motion]]`, or Markdown link format, e.g. `[Three laws of motion](Three%20laws%20of%20motion)`.
- Obsidian says Wikilink is generated by default because it is more compact, while Markdown links can be used when interoperability is important.
- Obsidian supports links to headings and blocks, but block references are Obsidian-specific and not standard Markdown.

Implication for M0.3:

```text
MINIMUM_LINK_PATTERN_CANDIDATE = Wikilink note-to-note links only
AVOID_FOR_M0_3 = block references as required contract
RATIONALE = keep convention compact, visible, easy to inspect, and not dependent on non-standard block-level behavior
```

### Source 2 — Obsidian Help: Properties

Provenance:

```text
SOURCE_TITLE = Properties - Obsidian Help
SOURCE_URL = https://obsidian.md/help/properties
SOURCE_TYPE = official vendor help page
RETRIEVED_DATE = 2026-07-09
REVIEW_STATE = staged_only
```

Relevant finding:

- Obsidian properties are structured metadata stored in YAML at the top of a note.
- Properties can include text, lists, dates, checkboxes, numbers and tags.
- Obsidian permits internal links in text/list properties when surrounded with quotes.
- Markdown formatting is not rendered inside properties; properties are meant for small atomic information that is human and machine readable.

Implication for M0.3:

```text
MINIMUM_METADATA_PATTERN_CANDIDATE = preserve existing YAML front matter, but keep graph navigation visible in note body sections first
PROPERTY_LINKS_FOR_M0_3 = optional / not required for initial navigation acceptance
RATIONALE = reduce hidden authority risk; visible body links are easier for a user and reviewer to inspect
```
